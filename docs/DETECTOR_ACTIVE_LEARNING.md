# Improve a detector from a local best.pt

This walkthrough starts with a trained Ultralytics **object detector** and ends with an independently evaluated successor. Keep each checkpoint in the project under a distinct name, such as `Polyp R0`, `Polyp R1`, and `Polyp R2`.

## Prepare the reference and acquisition images

1. Establish which specimens, colonies, dives or recordings contributed to the starting model. Reserve independent groups with reference labels for validation and final testing. If the starting model's training history is unknown, use newly collected independent groups and record that limitation.
2. In **Gallery → Image details**, give related images the same **Group key**, including tiles and repeat views. Review the seed annotations and reference labels. For a true negative, inspect the whole frame and save it as **Reviewed** with zero boxes. An unexamined frame belongs in the acquisition pool.
3. In **Dataset versions**, freeze the reviewed baseline. Use **Manual split assignment** to preserve a preassigned study design, or a group-aware split to establish it. **Preview snapshot**, check group membership and counts for train, validation and test, then **Create immutable version**. Record the version and manifest. Keep these validation and test observations fixed across rounds.
4. Import the acquisition batch from independent training-eligible groups. To freeze this batch, create a separate version with **Unannotated** as its only eligible status and no split assignment. Check the preview because the status applies across the project. Avoid including other unreviewed batches. Dataset membership and original labels in this pool stay frozen while new proposal jobs supply the acquisition signal.

## Register R0 and collect proposals

1. Open **Models & AI → Model Hub → Register Existing Model**. Choose **Detector**, the Ultralytics provider and your local `best.pt`. Set the display name and document the source dataset and class ordering in **Notes**. Verify the origin of the file and select its file-specific trust confirmation before registering it. Record its SHA-256.
2. Inspect its class mappings in **Registered Models**. Registration matches active project classes by name and can create a class for a new name. Resolve differences in the project taxonomy before accepting predictions. A class marked *Unmapped* requires attention. The detector's class names and biological definitions must agree with the reference labels.
3. In **Gallery**, select the acquisition images using their checkboxes. In the inference inspector choose **Detector model**, **Confidence threshold**, and **Device**, then **Run model on selected images**. Record the model, image set and settings. A high threshold can hide uncertain proposals. A model-filtered acquisition only includes images with proposals from that model. Inspect a sample of zero-proposal images separately for missed objects.

## Review one round

1. Open **Models & AI → Active learning**. Give the round a name, choose the frozen pool under **Input dataset**, select **Uncertainty**, check R0 under **Model filter**, and enter a **Review budget** in images. Select **Create round**. The frozen input limits the roster. Training and unassigned items are eligible. Validation and test items in that version are excluded. Every round, including **Current project state**, also excludes historical test images across the project. ReefVision follows image IDs, source-file checksums and non-null group keys across current images and earlier frozen versions. A renamed group or a second acquisition pool preserves that protection. Give new related observations their correct group key before running acquisition.
2. Inspect **Why these images?** and the selected count. Use **Open Review Queue** for this round. Open each selected image, inspect the entire frame, correct inaccurate geometry, reject false positives, accept correct proposals and draw missing objects. Save the image as **Reviewed**. Enter a reviewer label in the queue and **Mark complete**. If the image cannot be interpreted, use **Skip** and record the reason.
3. In **Active learning**, select the same round and choose **Complete round + snapshot feedback**. A round with at least one completed image produces an immutable snapshot of currently reviewed project images outside the historical test groups. Existing parent assignments are reused and newly allocated groups go to training. An all-skipped round has no feedback dataset. Record the selection manifest, feedback version and completed image IDs.

## Fine-tune R1 and compare it with R0

1. Build the training version in **Dataset versions**. Choose the previous **training** version as **Parent version**, enable **Reuse compatible split assignments from the selected parent version**, and include only **Reviewed** images. Select **Manual split assignment**, preview, then assign newly reviewed acquisition groups to **Train**. Verify that the original validation and test groups, image identities, counts, and reference labels match the baseline. Freeze this version and record its manifest. This step matters when the round's input was an unassigned acquisition pool. Its feedback snapshot inherits the pool's split history and may contain other reviewed project images.
2. Go to **Models & AI → Training → New draft**. Select the detection task. Open **Registered model initialization → Registered checkpoint** and choose R0. For later rounds, registered ReefVision training outputs appear in **My trained models**. Check that the draft shows **Registered model initialization** and the intended checkpoint. In **Dataset & Splits**, choose the training version just frozen. In **Hyperparameters**, set image size, epochs, batch size and early-stopping **Patience**. To prescribe an **Initial learning rate (lr0)**, choose **SGD**, **Adam** or **AdamW** under **Optimizer**, then enter the rate. **Auto** chooses its own rate and clears a manual override. Record the optimizer, rate or automatic mode, device, seed and validation split. Select **Start training**. Each detector round starts a new fit from the registered weights with a fresh optimizer and epoch counter. The detector workspace has no same-run resume control for an interrupted fit.
3. Inspect the completed run's validation metrics and checkpoint. Use **Register best detector** and give it a generation-specific name. Record the incoming model checksum, training version and split manifest, run ID and resulting model checksum.
4. Use validation to decide whether to adopt R1. Compare validation results on identical images, classes, reference boxes, confidence threshold and IoU rule. Inspect false positives, missed objects and count errors by independent group alongside precision and recall. Keep the earlier model available if R1 fails your criteria. Once development and thresholds are fixed, open **Local model runtime** in Model Hub for each checkpoint, select matching inference settings, choose **Preview local configuration**, then **Confirm reviewed configuration**. Open **Models & AI → Model comparison**, choose the two reviewed configurations and the original frozen reference, then select **Run paired comparison**. The detector comparison reads the frozen dataset's **Test** split and requires an explicit group key for every test image. Evaluate the reserved test once. Export the JSON report and group-level CSV, and preserve the reported lineage status. Imported weights with incomplete recorded ancestry yield an exploratory result. Further changes informed by that result require fresh independent test groups for a new final claim.

For R2, repeat with the remaining acquisition images, select R1 for inference and acquisition, and use the R1 training dataset as the parent. Rebuild the remaining pool after review because an earlier frozen pool still contains its original members. The review budget counts images, so record actual annotation effort if comparing review strategies. A completed run establishes software execution. Improvement on new underwater observations requires independent labels and a prespecified decision criterion.

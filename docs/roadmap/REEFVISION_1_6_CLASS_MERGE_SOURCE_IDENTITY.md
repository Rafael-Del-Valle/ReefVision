# ReefVision 1.6: reviewed class-merge source biological identity

A reviewed class-usage inventory binds a merge to the **identities of existing scientific references**. That fingerprint and the previous target-identity comparison do not protect against changing the **source class** name, class index, scientific name or biological state after the researcher reviewed the merge. The same annotation IDs and counts would then be transferred into a target under a different biological interpretation.

The Class Manager confirmation now explicitly identifies both source and target semantic fields, and transmits `expected_source_identity` alongside reviewed counts, the immutable source reference-ID fingerprint and `expected_target_identity`. The backend rejects a changed source identity with HTTP 409 **before any merge writes**. Source identity is optional for older local API clients, while the 1.6 GUI always sends it. Cosmetic color, description and display order are excluded; these cannot change the biological class identity. The existing reviewed-use and target checks remain required in the GUI.

The real-database class usage/merge regression now edits the source biological state without changing reference IDs or counts, verifies the new rejection while preserving active annotations and QC references, restores the state, then confirms the authorized merge succeeds with both source and target approval snapshots. The component regression checks exact source/target snapshots and confirmation text.

This is a pre-write optimistic check, **not** an atomic lock against concurrent class edits between validation and commit. It does not certify taxonomy or biological correctness. Class metadata merges are manual review operations, not standalone scientific analyses requiring a duplicate Workflow Builder node. Existing typed executable QC workflow nodes, saved runs, provenance and researcher-review gates remain unchanged. Native Windows installation/upgrade and installed-GUI testing, representative biological acceptance and cross-version Alembic reconciliation are outstanding.

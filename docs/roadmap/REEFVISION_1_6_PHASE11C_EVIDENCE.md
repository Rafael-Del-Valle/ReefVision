# ReefVision 1.6 — invocation-bound Windows acceptance evidence

The **Track D 1.6** `scripts/phase11c-acceptance.ps1 -TrackD16` wrapper now generates a random 12-character lowercase hexadecimal acceptance token and passes it to the existing disposable clean-install harness with `-EvidenceToken`. The child writes its report only under `.artifacts/windows-clean-acceptance-<token>/report.json` and refuses an already-existing evidence or run directory. Its report also records `evidence_run_token`. The wrapper requires the exact token and corresponding `reefvision-clean-<token>/data` run directory before invoking the independent installed-science report validator.

This removes a false-attribution race: two simultaneous clean-install jobs may each produce a valid new report, but only the report tied to the *current* parent invocation can be evaluated. A missing, stale or mismatched report fails closed. An unrelated concurrent run does not spuriously cause rejection. Historical Phase 11C mode retains its prior unique-new-directory selector, and direct clean-install runs without `-EvidenceToken` retain their generated-token behavior. `-PlanOnly` remains a non-installing dry run and does not imply a release-ready installed-GUI result.

**Regressions:** `scripts/test-phase11c-report-selection.ps1` exercises native Windows PowerShell token shape, rejection of malformed/path-like tokens, legacy report selection and exact-head checks. `apps/api/reefvision/tests/test_phase11c_acceptance_contract.py` checks wrapper/child token handoff and fail-closed report binding. CI runs the native PowerShell script in the Windows research-preservation job. The existing installed-science validator still requires class visibility, QC review and executable persisted/replayed typed Workflow Builder evidence with scientific provenance and explicit researcher review.

**Release status: HOLD.** This is an evidence-attribution improvement, **not** a genuine installed Windows MSI/CAB acceptance result.
